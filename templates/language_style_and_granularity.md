# 语言风格与颗粒度规范

## 语言风格决策规则

输出文档的语言风格和排版规范应由用户决定。AI 可以提供默认建议，但不能把默认建议当成用户已确认规范。

在正式撰写主策划案前，AI 应提问确认：

```text
【问题】
本策划案采用哪种语言风格和排版规范？

【选项】
A. 专业实现型【AI 推荐】
   适合程序、测试、制作人评审；强调规则、状态、边界和验收。

B. 评审汇报型
   适合向负责人或跨部门说明；强调目标、取舍、风险和结论。

C. 配置落地型
   适合进入开发；强调字段、配置、任务和验收。

D. 用户自定义
E. 提供更多选择
F. 追问 AI
```

确认后写入 `workflow_state.md` 或主策划案文档信息区。

## AI 默认语言风格

```text
专业
直接
结构化
低歧义
面向实现
便于评审
便于拆需求
```

## 写作规则

```text
1. 少用感性描述，多用可观察行为。
2. 少用模糊词，多写条件、规则、状态、结果。
3. 区分设计目标和实现方案。
4. 区分已确认内容和待确认内容。
5. 不把 AI 推断写成正式结论。
6. 重要规则必须包含触发条件、执行结果和边界情况。
7. 验收标准必须可检查。
8. 排版规范以用户确认版本为准。
```

## 默认排版规范

```text
1. 标题层级最多到四级。
2. 关键规则优先使用表格或短条目。
3. 长流程使用 Mermaid 或图片辅助。
4. 每个表格必须有明确列名。
5. 已确认、待确认、已补齐默认方案必须显式标注。
6. 岗位版本可以更短，但不得省略不可妥协项。
```

## 慎用词

以下词语可以使用，但必须补充明确规则或量化说明：

```text
好玩
丰富
适当
大量
明显
较高概率
差不多
看情况
以后再说
```

## 颗粒度分级

### L1 概念颗粒度

适用于方向讨论。

说明：

```text
为什么做
做什么
核心体验是什么
```

### L2 规则颗粒度

适用于方案评审。

说明：

```text
玩家流程
系统规则
状态变化
奖励逻辑
边界情况
```

### L3 实现需求颗粒度

适用于进入开发。

说明：

```text
触发条件
字段或配置项
UI 状态
异常处理
验收标准
测试点
```

## MVP 默认颗粒度

```text
L2 规则颗粒度 + 关键部分 L3 实现需求颗粒度
```

必须达到 L3 的内容：

```text
核心规则
触发条件
状态变化
奖励/消耗
刷新/重置逻辑
异常与边界
UI 关键状态
配置项
验收标准
测试点
```

可以暂时保持 L2 或待确认的内容：

```text
未确认美术表现
未确认数值参数
可替代实现方式
低风险文案
暂未确定运营参数
```

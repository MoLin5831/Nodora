# 整案评审清单

本清单用于 AI 对完整主策划案进行评审。

## 评审输出格式

```text
总体结论：

必须修改：
1.

建议优化：
1.

待用户决策：
1.

可暂缓：
1.

下一步建议：
```

## 1. 完整性检查

- 是否包含背景、目标、方案、规则、风险、验收标准。
- 是否说明为什么要做。
- 是否说明为什么这样做。
- 是否有明确不做范围。
- 是否有待确认问题清单。

## 2. 前后矛盾检查

- 刷新时间是否一致。
- 奖励发放规则是否一致。
- UI 展示状态是否与系统规则一致。
- 术语是否前后一致。
- 岗位需求是否与主规则一致。

## 3. 规则闭环检查

- 是否有触发条件。
- 是否有执行逻辑。
- 是否有执行结果。
- 是否有状态变化。
- 是否有失败或异常处理。
- 是否有重复操作处理。
- 是否有跨天、断线、重连、补偿等边界。

## 4. 风险与取舍检查

- 是否说明被放弃的方案。
- 是否说明选择当前方案的原因。
- 是否标注不可妥协项。
- 是否标注可调整项。
- 是否存在实现成本被低估的问题。

## 5. 可执行性检查

- 程序是否能从文档中理解规则。
- UI 是否能从文档中理解页面和状态。
- 测试是否能从文档中提取测试点。
- 数值和配置项是否足够明确。
- 验收标准是否可验证。

## 6. 表达质量检查

- 是否存在模糊词。
- 是否有过多感性描述。
- 是否把目标和方案混在一起。
- 是否把 AI 推断写成正式结论。
- 是否存在长段落难以阅读的问题。

## 7. 岗位可读性检查

- 程序关心的规则、状态、异常是否清楚。
- UI 关心的信息层级、交互、状态反馈是否清楚。
- 测试关心的边界和预期结果是否清楚。
- 管理评审关心的目标、范围、风险是否清楚。

## 8. 评审严重度

```text
P0：会导致需求错误或无法开发，必须修改。
P1：会导致理解偏差或返工，建议修改。
P2：影响阅读效率或文档质量，可优化。
P3：后续迭代中可补充。
```

# 用户改稿检查规则

本规则用于处理用户手动修改 AI 已生成文档后的场景。

## 核心原则

```text
用户可以直接修改任何 Markdown 文档。
AI 必须能读取、理解并检查用户改稿。
AI 不得默认用户改稿是错误的，也不得擅自回滚用户改稿。
```

## 检查流程

当用户说“我改了文档”“检查我的修改”“理解这次改稿”时，AI 应执行：

```text
1. 读取用户修改过的文件。
2. 对照主策划案、设计决策记录、待确认问题和变更记录。
3. 判断改稿属于哪一类：
   - 明确补充
   - 表达优化
   - 规则变化
   - 状态变化
   - 与已有决策冲突
   - 引入新的待确认问题
4. 输出检查结果。
5. 如需同步其他文件，先说明将同步哪些文件，再等待用户确认或执行用户明确要求。
```

## 输出格式

```text
【改稿理解】
- 用户新增/修改了什么：
- 这是否改变设计原意：
- 影响哪些章节或岗位：

【一致性检查】
- 与主策划案是否一致：
- 与设计决策记录是否一致：
- 与待确认问题状态是否一致：
- 是否需要更新岗位版本或任务单：

【建议动作】
A. 接受修改并同步相关文件
B. 只保留当前文件修改，不同步
C. 将修改转为待确认问题
D. 回到 AI 提问流程重新决策
E. 提供更多选择
F. 追问 AI
```

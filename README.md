# Nodora

Nodora 是一个面向 AI 辅助决策的桌面端策划案工作流工具,适合策划、产品、内容、方案与项目文档工作。它不是普通 Markdown 编辑器，也不是零散的 AI 对话工具集合，而是围绕“从需求澄清到策划案成稿、评审、转译、归档”的完整闭环来设计。
它的核心目标是：帮助用户把一个模糊想法，逐步推进成结构清晰、依据充分、可评审、可复用的正式策划案。

## 为什么需要 Nodora

很多 AI 写作工具能快速生成一篇文档，但真正的策划工作并不只是“让 AI 写一段内容”。
一份成熟的策划案通常需要经历：
- 明确项目背景和目标
- 梳理关键问题
- 确认方案边界
- 搭建文档框架
- 统一语言风格和格式
- 分章节撰写正文
- 检查逻辑漏洞和风险
- 根据不同岗位转译版本
- 归档过程经验和项目记忆
这些步骤如果全部靠用户手动管理，很容易出现上下文丢失、版本混乱、AI 输出不可控、文档越写越散的问题。
Nodora 试图解决的正是这个问题：让 AI 不只是“写字”，而是参与到策划案推进过程中的判断、追问、评审和整理。

## 核心能力

### 1. 策划案闭环
Nodora 内置完整的策划案工作流，从项目入口、背景建档、AI 澄清提问、框架评审、目录生成、风格确认、分章节撰写，到整案评审、岗位转译、归档和记忆更新。
用户不需要自己设计流程，系统会根据当前阶段提示下一步该做什么，避免策划案写作停留在“想到哪写到哪”的状态。

### 2. AI 决策式推进
Nodora 的重点不是让 AI 一次性生成完整文档，而是让 AI 在关键节点提出问题、给出选项、辅助判断。
例如：
- 当前信息是否足够进入正式写作
- 哪些问题必须先确认
- 哪些章节还缺事实依据
- 当前评审中是否存在必须修复的问题
- 下一步应该继续写作、回到澄清，还是进入评审
这种方式能让用户保持主导权，同时降低组织复杂文档的负担。

### 3. 项目文件工作区
Nodora 支持面向项目目录的文件工作流，通过Tauri 桌面桥接来支持选定项目目录、本地文件操作、导出能力和模型 API 代理。可以读取项目内文档、查看目录结构、生成文件摘要，并在用户确认后执行写入、归档等操作。
关键文件和记忆区域受到保护，不会绕过用户确认直接改写主策划案或项目记忆。

### 4. 多会话 AI 对话
Nodora 支持多会话 AI 对话页签和持久化，适合把不同主题、不同阶段、不同问题分开讨论。
用户可以在同一个项目中保留多条思考线索，不必反复复制上下文。

### 5. 联网研究闭环
Nodora 支持 AI 发起联网研究请求，通过搜索、抓取网页正文摘录、整理来源和证据，再回填给 AI 生成研究报告。
这让策划案不只依赖模型已有知识，也可以结合最新资料、竞品信息、行业背景和外部证据。

### 6. 本机安全存储 API Key
桌面版会优先将模型 API Key 保存到本机安全存储中。若 Windows Credential Manager 不可用，也会使用 Windows DPAPI 加密 fallback，避免用户每次启动都重新输入，同时不把 API Key 长期明文保存到项目文件中。

### 7. 文档预览与导出
Nodora 支持 Markdown 内容预览、Mermaid 图表渲染、Word/PDF 导出能力，适合将策划过程中的阶段性成果整理成可交付文档。
视觉资产不会直接生成图片，而是在文档中标注需要什么类型的图片，方便后续由设计或用户自行补充。

## 适合谁使用

Nodora 适合这些场景：
- 产品经理撰写产品方案、PRD、功能策划
- 游戏策划整理系统设计、玩法设计、数值说明
- 内容策划撰写活动方案、栏目方案、传播方案
- 创业者整理项目方案、商业计划、产品构想
- 团队成员把零散想法沉淀成结构化文档
- 需要反复评审、修订、转译和归档的复杂文档工作

## 当前阶段

Nodora 目前处于早期预览阶段，已经具备核心工作流、AI 对话、项目文件任务、联网研究、本机模型配置和文档导出等基础能力。
后续会继续围绕“AI 决策式策划案工作流”完善体验，包括更清晰的流程状态、更成熟的项目模板、更强的评审能力，以及更适合真实团队协作的文档管理方式。

## 安全模型

- 受保护写入必须经过用户确认后才会修改项目文件。
- 本地文件访问限定在用户选择的项目根目录内。
- Tauri 桌面版会把模型 API Key 保存到操作系统凭据库，不写入项目目录；浏览器回退模式只在当前会话中保留 Key。

更多细节见 [SECURITY.md](SECURITY.md)。

## 环境要求

- Node.js 20 或更高版本。
- npm 10 或更高版本。
- Tauri 桌面开发所需的 Rust 工具链。
- Microsoft Edge 或 Google Chrome，用于桌面端 PDF 导出。

## 本地初始化

```powershell
cd app
npm install
Copy-Item .env.example .env
```

`app/.env.example` 当前只包含：

```env
NODORA_CONFIG_ENV=development
```

不要把 API Key、Token、生产密钥、服务器密码或本机路径写入 `.env.example`。真实 `.env` 文件必须保留在本地。

## 开发命令

运行 Web 版本：

```powershell
cd app
npm run dev
```

运行 Tauri 桌面版本：

```powershell
cd app
npm run tauri:dev
```

运行前端测试和构建：

```powershell
cd app
npm test
npm run build
```

如果修改了 Rust 后端代码，还需要运行：

```powershell
cd app\src-tauri
cargo test
```
